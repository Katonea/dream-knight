## 0. 에이전트에게 — 먼저 읽을 것

### 0.1 이 문서를 쓰는 법

1. **§1~§3**을 읽어 무엇을, 왜 만드는지 파악한다.
2. **§4 구현 지시**의 기술 스택과 코드 구조를 그대로 따른다.
3. **§5 태스크 분해**를 M0부터 순서대로 진행한다. 마일스톤마다 *완료 조건*을 브라우저 콘솔에서 통과해야 다음으로 넘어간다.
4. 수치·공식·이름은 **§6~§9 데이터 표**에서 가져온다. 표의 값을 임의로 바꾸지 않는다.
5. 판단이 애매하면 **§10 판단 가이드**를 본다. 거기에도 없으면 더 단순한 쪽을 고르고, 그 결정을 코드에 `// DECISION:` 주석으로 남긴다.
6. **§11 알려진 함정**을 구현 전에 한 번 읽는다. 앞선 구현에서 실제로 터진 버그와 그 해법이다.
7. 끝나면 **§12 검증 기준**을 전부 돌리고 §12.5 형식으로 보고한다.

### 0.2 용어 규칙

| 표기 | 뜻 |
|---|---|
| **MUST** | 반드시 구현한다. 빠지면 프로토타입 실패 |
| **SHOULD** | 구현을 권장한다. 시간이 부족하면 생략하되 보고서에 생략 사실을 적는다 |
| **WON'T** | 이번 범위에서 만들지 않는다. 만들면 감점 |
| m, m/s | 게임 월드 단위. **1 m = 블록 1칸** |
| s | 초. 게임 내 시간이다. 일시정지·레벨업 중에는 흐르지 않는다 |
| 논리 px | 스프라이트를 그릴 때 쓰는 픽셀 좌표 (§10.1) |

### 0.3 절대 하지 말 것 (WON'T)

- 외부 이미지·사운드·폰트 에셋 파일. 그래픽은 전부 코드로 생성한다. 예외는 웹폰트 Noto Sans KR 하나다
- npm·번들러·빌드 단계. 파일 하나를 브라우저로 열면 동작해야 한다
- 물리 엔진, 실시간 그림자, PBR 조명, 포스트프로세싱 라이브러리
- 계정·로그인·서버·메타 성장(영구 업그레이드)·상점·광고·결제. **예외(v2.2)**: ① 설정(소리·진동·지도 방향·닉네임·내 기록)은 `localStorage`에 저장한다 ② 랭킹은 저장소의 `ranking.json`을 읽고 GitHub 이슈로 등록한다(§10.6). 그 밖의 저장·불러오기는 만들지 않는다
- 블록 캐기·설치. 지형은 보기만 하고 바꿀 수 없다
- 표에 없는 기술·유물·몬스터
- 고해상도 렌더. 3D는 반드시 저해상도 픽셀로 그린다(§4.5). 앞선 구현에서 고해상도로 올렸다가 "픽셀 느낌이 사라져 오히려 저품질로 보인다"는 판정으로 되돌렸다

## 1. 게임 컨셉 및 핵심 재미 가설

### 1.1 한 줄 요약

**"밤의 꿈나라에서 10분 동안 몰려드는 악몽을 자동 공격으로 쓸어내며, 레벨업 카드로 나만의 원소 빌드를 완성하고 구역 수호자를 쓰러뜨리는 3인칭 픽셀 서바이버."**

### 1.2 기본 정보

| 항목 | 내용 |
|---|---|
| 장르 | 서바이버라이크(Survivor-like) 액션 · 글로벌 캐주얼 |
| 시점 | 3인칭 숄더뷰. 캐릭터 등 뒤 위쪽에서 내려다보며, 카메라를 돌릴 수 있다 |
| 아트 | 블록 지형(3D) + 2D 픽셀 스프라이트 생물(빌보드). 화면 전체를 약 480×270으로 그린 뒤 확대한다 |
| 플랫폼 | 데스크톱 브라우저(키보드+마우스) 우선, 모바일 브라우저(터치) 지원 |
| 1판 길이 | 구역 3개 × 약 6~10분 = 20~30분. 구역 1개만 해도 완결감이 있어야 한다 |
| 조작 | 이동 + 점프 + 상호작용(E) + 궁극기(R). **공격은 전부 자동**. 모바일 가로 화면은 전용 터치 UI(§10.3.1) |
| 타깃 | 서바이버라이크·로그라이트 입문자, 짧은 세션을 선호하는 캐주얼 유저 (10대 후반~30대) |

### 1.3 세계관 (UI 문구 톤 기준용)

- 사람들이 꾸는 꿈 세계에 악몽이 번졌다. 양 떼는 잠들지 못하고, 이불과 장난감이 몬스터가 되어 몰려온다.
- 플레이어는 파란 망토의 **악몽 탐험가**다. 크림색 둥근 가면에 초승달 투구를 쓴 꼬마 기사다. 판을 시작할 때 **시작 기술 3개 중 하나**(불티 화살·물살 화살·추적 가시씨)를 골라 들고 들어간다.
- 구역마다 잠든 **수호자**(그 꿈 주인의 가장 큰 악몽)를 깨워 쓰러뜨리고 포털을 연다.
- 문구 톤은 친근한 해요체로 짧게 쓴다. 예: "포털이 열렸어요", "코인이 부족해요".
- 캐릭터는 기존 IP를 흉내 내지 않는다. 특정 게임 캐릭터의 은색 가면, V자 눈구멍, 박쥐 날개 같은 고유 요소는 쓰지 않는다.

### 1.4 핵심 재미 가설

각 가설은 **§12.3의 측정 지표**로 검증한다.

| # | 가설 | 이걸 만드는 장치 | 실패 신호 |
|---|---|---|---|
| H1 | **성장 쾌감**: "처음엔 몇 마리에 쩔쩔매던 내가 9분엔 화면을 쓸어버린다"는 체감이 핵심 재미다 | 적 수 증가 곡선 + 레벨업 카드 + 각성(외형 변화) + 궁극기 + 기술별 이펙트 | 분당 처치 수가 시간에 따라 늘지 않음 / 5분 이후 지루하다는 응답 |
| H2 | **빌드 선택의 재미**: 3장 중 1장 고르기가 매번 의미 있는 선택이다 | 기술 4슬롯 + 룬 3슬롯 + 희귀도 + 원소 반응 6종 + 아이콘으로 한눈에 구분 | 카드를 안 읽고 1번만 누름 / 판마다 빌드가 같음 |
| H3 | **입체 지형이 전술을 만든다**: 점프로 고원에 올라가면 숨 돌릴 수 있다는 걸 스스로 발견한다 | 점프(공중 점프는 바람 망토로 해금), 1칸 턱 자동 오르기, 적은 절벽을 느리게 기어오름, 높이 차 1.4 m 이상이면 접촉 피해 없음 | 점프를 거의 안 씀 / 고원이 그냥 장애물로만 느껴짐 |
| H4 | **명확한 목표가 짧은 세션을 붙잡는다**: "제단 → 수호자 → 포털"이 보이면 끝까지 한다 | 미니맵의 빨간 점(수호자 제단), 600초 대범람 압박, 구역 클리어 연출 | 수호자를 안 깨우고 시간만 버팀 / 길을 잃음 |

## 2. Core Loop 정의 및 플레이 흐름

### 2.1 세 겹의 루프

```
[마이크로 루프 · 1~5초]
  이동/점프로 위치 잡기 → 자동 공격이 적 처치 → 꿈 조각(경험치) 떨어짐 → 다가가서 흡수
        │ (경험치 바가 참)
        ▼
[메조 루프 · 15~60초]
  레벨업 → 게임 정지 → 카드 3장 중 1장 선택(새 기술 / 기술 강화 / 룬) → 재개, 더 강해짐
        │ (틈틈이)
        ├─ 꿈 상인과 거래(코인) → 유물 3개 중 1개
        ├─ 룬 비석 위에 서서 충전 → 가호 3개 중 1개
        └─ 거대 개체 처치 → 무료 상자
        │ (준비가 됐다고 느끼면)
        ▼
[매크로 루프 · 6~10분, 구역 1개]
  수호자 제단을 찾아가 E로 깨움 → 보스전 → 처치 → 가호 + 무료 상자 → 포털 진입 → 다음 구역(더 강한 적, 다른 바이옴)
        │ (구역 3 클리어 또는 사망)
        ▼
  결과 화면(점수·메달) → 다시 하기
```

**프로토타입의 Core Loop 완성 조건**은 위 세 루프가 끊김 없이 돌아가는 것이다. 구체적인 판정은 §12.1.

### 2.2 플레이 흐름 (화면 단위)

| 순서 | 화면/상태 | 들어오는 조건 | 나가는 조건 | 게임 시간 |
|---|---|---|---|---|
| 1 | **타이틀** (`menu`) | 첫 로드 / 결과 화면에서 다시 하기 | 시작 기술·난이도를 고르고 시작(Enter) | 정지 |
| 2 | **플레이** (`play`) | 시작 / 모달 닫힘 | 레벨업, 상인·상자, 가호, 일시정지, 포털, 사망 | 흐름 |
| 3 | **레벨업** (`levelup`) | 경험치가 차면 즉시 | 카드 선택 / 건너뛰기. 대기 중인 레벨업이 남아 있으면 다시 레벨업 | 정지 |
| 4 | **선택** (`choice`) | 꿈 상인과 거래, 무료 상자 열기, 룬 비석 충전 완료, 보스 처치 0.6초 후 | 1개 선택 / (상인·상자만) 거절·팔기 | 정지 |
| 5 | **일시정지** (`pause`) | Esc·P / 창 포커스 잃음 | Esc·P / 포기하기(Q) | 정지 |
| 6 | **구역 전환** (`transition`) | 포털 진입(구역 1·2) | 1.1초 후 다음 구역 생성 | 정지 |
| 7 | **결과** (`over`) | HP 0 / 구역 3 포털 진입 | 다시 하기(Enter) | 정지 |

상태 머신은 **이 7개만** 쓴다. `G.state` 문자열 하나로 관리한다. `update()`는 `G.state === 'play'`일 때만 돈다.

### 2.3 첫 1분 경험 (튜토리얼 없이 배우게 하기)

| 시점 | 일어나는 일 | 의도 |
|---|---|---|
| 0초 | 꿈 들판 한가운데 평평한 초원(반경 16 m)에서 시작. 화면 중앙에 "구역 1 / 꿈 들판" + 날씨 배너 | 안전한 출발점 |
| 0~3초 | 적이 38 m 밖에서 땅을 뚫고 솟아올라(§10.1.7) 걸어온다. 시작 기술이 자동 발사된다 | 공격이 자동이라는 걸 몸으로 알게 함 |
| 20~35초 | 첫 레벨업. 카드 3장 중 최소 1장은 기술 카드 | 첫 선택은 쉽게 |
| 상시 | 화면 아래 힌트 줄: "Space 점프(공중 점프는 바람 망토를 먹어야) · 마우스 이동 시점 · ← → 카메라 회전 · 휠 줌 · E 상호작용 · R 궁극기" | 점프·카메라를 알려 줌 |
| 60초 | "새 몬스터 등장: ○○" 토스트 | 변화의 리듬 |
| 근처 오브젝트 | 2.4 m 안으로 가면 "E · 보물 상자 열기 (20◆)" 같은 프롬프트 | 상호작용 발견 |

## 3. 게임 규칙 요약 (한 장 정리)

- 구역 3개: **꿈 들판(밤) → 모래시계 사막(황금빛 노을) → 별 내리는 눈숲(황혼)**. 구역마다 지형·몬스터·보스가 다르다.
- 구역마다 수호자 제단이 1개 있다(맵 중심에서 52~76 m). E로 깨우면 보스전이 시작된다.
- 보스를 잡으면 포털이 생긴다. 포털에 들어가면 다음 구역으로 간다. 구역 3이면 승리다.
- 구역 타이머는 **남은 시간**이 10:00에서 줄어든다. 0이 되면 **최후의 무리**가 시작되고 타이머가 `+00:00`부터 올라간다. 최후의 무리는 생성 속도 ×6, 초당 약 2번 정예 6마리, 그리고 새로 나오는 적의 HP가 분마다 ×4, 피해가 분마다 ×2로 불어난다. 시간을 끌수록 불리하다.
- HP가 0이 되면 패배다. 부활은 없다.
- 레벨업할 때마다 카드 1장을 고른다. 기술 슬롯은 3개(구역 2부터 4개), 룬 슬롯은 3개다.
- 코인(◆)으로 **꿈 상인**에게 유물을 산다. 거래 가격은 거래할 때마다 1.3배가 된다. 무료 상자는 그대로 상자다.
- 일부 몬스터(이불 유령·서리 나방·시계 부엉이·태엽 로봇·번개 해파리)는 멀리서 탄을 쏜다. 고원 위에 올라가면(높이 차 1.6 m 이상) 맞지 않는다.
- 플레이어는 몬스터를 통과하지 못한다(같은 높이 1.2 m 안). 점프하거나 고원에 올라가면 넘어간다. 피격되면 때린 쪽 반대로 7 m/s로 밀리고(초당 감쇠 e^-10), 0.35초 동안 빨간 테두리가 생긴다.

## 4. 구현 지시

### 4.1 기술 스택 (MUST)

| 항목 | 지정 | 이유 |
|---|---|---|
| 언어 | 바닐라 JavaScript (ES2020). TypeScript 아님 | 빌드 없이 바로 실행 |
| 렌더링 | **three.js r128** — `https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js` (전역 `THREE`) | 버전 고정. r128은 UMD 빌드가 있어 `file://`로 열어도 동작 |
| 파일 구성 | **`index.html` 파일 하나** (HTML + `<style>` + `<script>`) | 에이전트는 한 파일만 관리하고, 사용자는 더블클릭으로 실행 |
| 폰트 | Google Fonts **Noto Sans KR** (400/700/900) | 한글 UI. 로드에 실패하면 `system-ui`로 대체 |
| UI | HTML/CSS DOM 오버레이(HUD·모달·카드). 데미지 숫자만 2D 캔버스 | 텍스트가 선명하고 구현이 단순 |
| 입력 | `keydown/keyup`, Pointer Events(마우스·터치 통합) | 모바일 지원 |
| 난수 | `Math.random()` + 지형 생성용 시드 PRNG(mulberry32) | 지형은 시드로 재현할 수 있어야 함 |

### 4.4 업데이트 순서 (MUST, 매 프레임 `dt = clamp(실제 경과, 0, 0.05)`)

`G.state === 'play'`일 때만 아래를 순서대로 실행한다. 히트스톱(`G.hitstop > 0`) 중에는 1~15를 건너뛰고 카메라·렌더만 한다.

1. `G.time`, `G.zoneTime`, `P.noHitT` 증가, `P.awakeT` 감소, 화력 측정(`trackDps`)과 지연 실행(`updateLater`)
2. 플레이어 이동(카메라 기준) · 몬스터와 겹침 밀어내기 · 피격 넉백 · 지형 충돌 · 점프 · 중력 (§7.3)
3. 무적 시간 감소, HP 재생
4. 궁극기 자연 충전, R 입력 처리
5. 날씨 효과 (비: 1.5초마다 주변 16 m 적에게 침수 2초)
6. 스폰 디렉터 (§8.3: 유효 시간으로 상한·생성, 타임라인 이벤트, 최후의 무리 정예)
7. 공간 해시 재구성 (셀 3 m). 5번 날씨 판정은 직전 프레임 해시를 읽으므로, 해시는 빈 칸 -1로 만들어 두고 구역을 만들 때 비운다(§11.1 함정 10)
8. 스킬 발동/지속 처리
9. 적 이동(행진·떼는 직선) · 보스 피해 상한 충전 · 상태이상 틱 · 접촉 피해 · 정리(compact) · 너무 먼 적(70 m 초과, 일반 적만)을 스폰 거리로 재배치
10. 공간 해시 재구성
11. 투사체·이펙트·파편 갱신
12. 보스 행동 → 중간 보스 → 위험 지대·충격파 → 선 공격·웅덩이 → 랜덤 이벤트·도전 제단 갱신 → 길 표시 시간 감소
13. 픽업(경험치·코인·회복·자석) 흡수
14. 룬 비석 충전, 가장 가까운 상호작용 대상 찾기, E 입력 처리
15. 입력 플래그 초기화 → 보스 처치 후 가호 타이머 → `G.levelQueue > 0`이면 레벨업 화면 열기

### 7.2 피해 공식

```
s = 기술 피해(§6.3 마지막 줄)
s *= damage × (cls == 'ph' ? physical : magic)
if 기술 원소 == 빌드 속성(P.el):       s *= 1.25        // 같은 원소 보너스. 빌드 속성 = 시작 기술의 원소(§7.4)
ef = CHART[공격원소][대상원소] ?? 1;   s *= ef; if ef > 1: s *= weakHit
if 날씨 강화 원소: s *= 1.3 ;  if 날씨 약화 원소: s *= 0.75
if 대상이 정예/거대/보스:             s *= eliteDamage
크리티컬 판정(critChance + 기술 crit) → s *= critDamage (+ 초크리)
유물 '대왕 망치' n개: 3%×n 확률로 s *= 8, "쾅!" 팝업
보스전 90초 초과: s *= 1 + (보스전 경과 − 90) × 0.02     // 장기전 방지
대상 빙결 중:                         s *= 1.2
원소 반응 판정(§6.2) → 배율 적용
상태이상 판정, 유물 '불붙은 화살촉' 점화 판정
유물 '사신의 낫': 보스가 아니고, 맞은 뒤 HP가 최대의 (4% + 4%×n) 미만이면 즉사
넉백: 6 m/s × knock (거대 2 m/s, 보스·중간 보스 0), 공격 지점에서 바깥 방향, e^(−8t)로 감쇠
유물 '뇌우 토템': 크리티컬이면 8 m 안 다른 적 1마리에게 낙뢰(피해 ×0.5, 연쇄 없음)
```

데미지 숫자: 흰색, 크리티컬 노랑(크게), 플레이어 피격 빨강. 동시 표시 상한은 일반 40개 / 크리 70개 / 전체 90개다(초과하면 오래된 것부터 삭제). 지속 피해(점화·중독)는 숫자를 띄우지 않는다.

### 7.3 이동·점프 (MUST, 수치 고정)

| 항목 | 값 |
|---|---|
| 이동 속도 | 6.2 m/s × moveSpeed. 물속(지면 높이 < 2이고 발 높이 < 2)이면 ×0.65 |
| 이동 기준 | 카메라 기준(W = 화면 안쪽). 카메라 앞 방향이 f = (cos yaw, sin yaw)이면 오른쪽은 (−sin yaw, cos yaw). 조이스틱도 같다 |
| 블록 오르기 | **마인크래프트처럼 걸어서는 못 오른다**(v2.2). 지면에서 다음 칸 높이 ≤ 현재 높이 + 0.05(같은 높이)까지만 걷고, 한 칸이라도 높으면 점프해야 한다(1단 점프 최고 1.49 m라 1칸은 넘고, 2칸 이상 턱은 바람 망토의 공중 점프가 필요). 공중에서는 다음 칸 ≤ 현재 높이 + 0.3까지. 자동 시뮬 봇만 예전처럼 1.05까지 걸어 올라 간다 |
| 충돌 | x축, y축을 따로 검사(벽에 비비며 미끄러지기). 진행 방향 앞 0.3 m 지점의 높이로 판정. 나무 칸은 높이 +8로 취급(통과 불가) |
| 점프 | 지면: 수직 속도 8.8 m/s. 공중: 남은 공중 점프가 있으면 8.2 m/s, 흰 입자 6개 |
| 중력 | 26 m/s² |
| 착지 | 낙하 속도 > 9 m/s로 착지하면 흔들림 0.15 + 먼지 8개. 착지하면 공중 점프 횟수 = floor(extraJumps) |
| 경계 | 월드 가장자리 2 m 안쪽으로 제한 |

> 참고: 이 수치로 1단 점프 최고 높이는 8.8²/(2×26) ≈ **1.49 m**, 2단 점프까지 쓰면(바람 망토 필요) 약 **2.8 m**다. 2칸 이상 턱은 2단 점프가 필요하다. M3 완료 조건은 이 계산에 맞춰져 있다.

**적의 지형 처리**: 다음 위치가 현재보다 1.05 m 넘게 높으면 수평 이동의 30%만 적용하고 초당 4 m씩 기어오른다. 낮아지면 초당 10 m로 내려간다. 나무 칸으로는 들어가지 않는다. **접촉 피해는 적과 플레이어의 높이 차가 1.4 m 미만일 때만** 준다. 적 투사체도 높이 차 1.6 m 이상이면 맞지 않는다. 접촉 판정 반경 = 적 반경 + 0.5 m. 빙결된 적은 접촉 피해가 없다.

### 7.4 레벨업 카드

**경험치 곡선**: 다음 레벨 필요량 `xpNext(L) = round((8 + 5.5L + L^1.8) × (L ≤ 2 ? 0.75 : 1))` (처음 두 레벨은 25% 싸다 — 블록 점프·적 밀림으로 초반 처치가 늦어진 것을 보정해 첫 레벨업을 20~35초에 맞춘다). 얻는 경험치 × xpGain × (1 + 0.25×난이도 인덱스).

**희귀도**

| idx | 이름 | 색 | 배율 m |
|---|---|---|---|
| 0 | 일반 | `#c8d0dc` | 1.0 |
| 1 | 고급 | `#5ad87a` | 1.2 |

**희귀도 롤 공식**

```
a = max(0, luck) / 100
o = 레벨 + luck/8 + (구역 − 1) × 12
ramp(e, t) = clamp((o − e) / (t − e), 0, 1)
가중치 = [ 70/(1+a),  24×(1+0.5a),  5×(1+a)²×ramp(3,10),  0.9×(1+a)³×ramp(8,18),  0.12×(1+a)⁴×ramp(14,26) ]
가중치에 비례해 하나 뽑기
```

**카드 후보 생성 규칙** (열 때마다 새로 생성)

1. 빈 기술 슬롯이 있으면:
   - **빌드 속성**(`P.el`) = 시작 기술의 속성(불·물·풀). 그 속성의 영웅(`HERO_ALL`에서 같은 원소)이 가진 전용 기술 4개(`P.sig`) 중 미보유·미추방이고 해금 레벨(0, 2, 4, 7) 이상인 것을 후보에 3번씩 넣는다("시그니처 기술" 태그). 주인공은 늘 파란 꿈지기(원소 물)지만 카드·같은 속성 피해 +25%·궁극기 속성은 `hero.el`이 아니라 `P.el`을 따른다. (v2.1까지는 `hero.el`을 써서 시작 기술과 상관없이 물 기술만 나왔다)
   - 60% 확률로 그 외 기술 1개를 추가한다(영웅 원소·중립 원소이거나, 35% 확률을 통과한 것 중에서)
2. 보유 기술 중 Lv8 미만·미추방이면 기술마다 강화 카드를 2번씩 넣는다(각각 희귀도 롤)
3. 룬: 보유 룬은 Lv10 미만이면 2번씩, 미보유 룬은 슬롯이 남았을 때 각각 45% 확률로 1번
4. 섞은 뒤 **첫 번째 기술 카드(새 기술/강화)를 맨 앞으로** 옮기고, 같은 대상 중복 없이 앞에서 3장
5. 후보가 0장이면 "코인 +20×구역" 카드 1장

**레벨업 도구**: 새로고침(F) 판당 2회 · 건너뛰기(X) 판당 2회(건너뛰면 코인 +5×구역) · 추방(Z) 판당 1회(누른 뒤 카드를 고르면 그 대상이 이번 판에서 다시 안 나온다). 숫자키 1~3으로 선택한다. 레벨업이 여러 번 쌓이면 모달을 닫지 않고 연속으로 띄운다(상단에 "남은 레벨업 n").

### 7.5 기술 슬롯·각성·궁극기

- **기술 슬롯**: 시작 3개(첫 칸에 영웅 첫 기술), **구역 2 진입 시 4개**. 4번째는 HUD에 "잠김 / 구역 2"로 표시한다.
- **각성**: Lv16에 1단계, Lv32에 2단계. 각성마다 기본 최대 HP +25%, 피해 +15%, 현재 HP를 최대의 50%만큼 회복, "각성! ★" 배너 + 이름 변경 + 외형 변경(날개·후광·햇살, §10.1.4). **조건은 레벨 16과 32뿐**이다(다른 조건 없음). **연출(v2.2)**: 0.6초 히트스톱 + 흔들림 최대, 하얀 플래시 → 금빛 플래시, 빛기둥(1.4초), 퍼지는 링 3겹(금·흰·망토색, 반지름 9·15·24 m), 나선으로 솟는 파편 110개, 플레이어가 금빛으로 번쩍(1.6초), 2.2초 무적, 15 m 안 일반 적을 밖으로 밀어내고 0.9초 기절 + 피해(60 + 6×레벨), 효과음(상승 스윕 + 화음), 진동. 각성 뒤에는 발밑 금빛 고리와 도는 별 알갱이(단계당 2개)가 항상 따라다닌다.
- **궁극기 게이지(0~1)**: 자연 충전 1/95 per s · 일반 처치 +0.004(단 "처치 충전 여유분" 0.024를 소모하고 여유분은 초당 0.024 회복 → 일반 처치로는 초당 최대 0.024) · 정예 +0.03 · 거대 +0.08 · 보스 +0.2 · 피격 시 (받은 피해/최대 HP)×0.35. 가득 차면 "궁극기 준비 완료!" 토스트.
- **궁극기 발동(R)**: 반경 12×√area m 원형, 피해 40×(1 + 0.1×레벨)×(1 + 0.15×각성), 영웅 원소 마법 피해, 상태 확률 100%(화염 = 점화, 물 = 침수, 숲 = 없음), 크리 +10%. 무적 1.2초, 히트스톱 0.32초, 흔들림 최대, 영웅 색 플래시, "○○의 궁극기!" 배너.

### 7.6 영웅 (1명 + 시작 기술 선택)

**사용하는 영웅은 tide(악몽 탐험가) 하나다.** pyro·grove는 데이터만 남겨 두고(`HERO_ALL`) 화면에는 내지 않는다(`HEROES = HERO_ALL.filter(h => h.id === 'tide')`). 대신 타이틀에서 **시작 기술**을 고른다: `START_SKILLS = ['fire_arrow', 'water_arrow', 'thorn_seed']`(기본 선택 water_arrow). 고른 기술이 첫 슬롯에 들어가고, 레벨업 시그니처 기술 후보는 tide의 4개 그대로다. 같은 원소 보너스(×1.25)는 물 기술에만 붙는다.

### 7.7 룬 (13종, 슬롯 3, 최대 Lv10)

구역별 등장 등급: 구역 1 = 0 / 구역 2 = 0, 1 / 구역 3 = 1, 2. 구역을 시작하면 해당 등급 중 무작위 2종으로 시작하고, `card` 이벤트마다 1종씩 추가한다. 풀에 원거리 몬스터가 없으면 그 `card`는 원거리 몬스터를 고른다(구역 1에서 원거리를 못 보고 끝나는 것 방지).

**스폰 시 스케일링** (t = 구역 경과 초, Z = 구역 배율 [1, 1.8, 3.2])

```
HP   = 기본 × (1 + t/60 × 0.18) × Z × 난이도.hp
피해 = 기본 × (1 + t/60 × 0.05) × Z^0.6 × 난이도.dmg
정예: HP ×5, 피해 ×1.5, 크기 ×1.3, 금색 바닥 고리
거대: HP ×14, 피해 ×1.8, 크기 ×1.7, 속도 ×0.85, 빨간 바닥 고리, 처치 시 무료 상자
정예 확률 = 0.012 + t/60 × 0.004 + (구역 − 1) × 0.03 + 난이도.elite
```

### 8.4.1 보스·웨이브·이벤트 시스템 (v2.2, MUST)

**동료(거대 개체를 잡아 부리는 것)는 넣지 않는다.**

**보스·중간 보스 HP = 화력 × 목표 시간** (고정 HP를 대체)
- 최근 10초의 피해 합으로 화력(`dpsNow`)을 잰다. 처음 HP = `화력 × 0.1 × 목표초 × (1 + 0.15×난이도)`를 기본 HP의 1~4배로 자른다.
- 싸우는 중 실제로 들어간 피해로 한 번 더 맞춘다(`refitHp`): 보스는 12초·30초, 중간 보스는 6초. `HP = 받은 피해 + 받은 피해 속도 × 남은 목표 시간`을 기본 HP의 1~4배로 자른다.
- 목표 시간(초): 수호자 40·50·60 / 우두머리 18·22·26 / 마술사 10·12·14 (구역 1·2·3).

## 9. 데이터 — 지형 생성

### 9.1 높이맵 알고리즘 (MUST, 순서대로)

맵은 180×180칸, 칸 = 1 m. `hmap`(높이, 정수 블록), `ttype`(블록 종류), `solid`(나무 있음) 배열을 쓴다. 구역마다 새 시드를 쓴다. 값 노이즈 `vn(x, y)`는 시드 기반 격자 해시를 smoothstep으로 보간한다.

1. **고원 위치**: 5개. 중심에서 28~78 m, 반지름 7~13, 높이 7~9, 서로 (r1 + r2 + 10) m 이상 떨어지게(개당 60회 시도).
2. **호수 위치**: 3개. 중심에서 22~77 m, 반지름 6~12, 고원·다른 호수와 (r1 + r2 + 5) m 이상.
3. **기본 높이**(v2.2에서 다양화): `n = vn(x/26, y/26)×0.62 + vn(x/11, y/11)×0.28 + vn(x/5, y/5)×0.1`, 능선 `ridge = (1 − |2·vn(x/20+40, y/20) − 1|)³`, **언덕 12개**(중심 14~76 m, 반지름 8~17, 높이 2~5.8, 4번째마다 음수 = 우묵한 계곡, 매끄러운 곡선 `t²(3−2t)`), `h = max(2, 2 + floor(n × 5.6 + ridge × 2.2 + 언덕합))` → 2~11칸(전엔 2~6). 높이 종류 평균 5개 → 11개, 표준편차 0.86 → 1.35.
4. **시작 초원**: 중심 반경 10 m 안은 높이 3으로 평탄화, 10~16 m는 서서히 섞기.
5. **호수**: 정규화 거리 d < 0.55 → 높이 0, d < 1 → 1, 1 ≤ d < 1.3이고 높이 ≤ 3 → 높이 2 호숫가(호숫가 블록). **그 밖에 d < 1.9면 높이 = min(h, 2 + floor((d − 1)×5))**. 호숫가가 1칸씩 오르는 비탈이 되어, 물에서 걸어서 나올 수 있다(MUST, §11.2).
6. **고원**: 중심 거리 < r + (노이즈 − 0.5)×3이면 높이 = 고원 높이, 종류 = 고원 블록(울퉁불퉁한 가장자리).
7. **가장자리 산맥**: 가장자리에서 5칸 안이면 높이 = max(h, 9 + (5 − 거리) + floor(노이즈×3)), 고원 블록.
7a. **비탈 깎기**(v2.2): 고원·가장자리 5칸·물을 뺀 땅은 이웃과 높이 차가 1을 넘으면 높은 쪽을 낮춘다(8번 반복). 점프 한 번으로 못 넘는 2칸 절벽이 고원 말고는 생기지 않게 하기 위해서다(공중 점프는 바람 망토가 있어야 하므로). 검증: 30개 맵에서 시작점에서 점프로 못 닿는 땅 0.1%.
8. **고원 계단 경사로**: 고원마다 무작위 방향 하나로 폭 3칸 계단을 낸다. (반지름 − 3) 지점부터 바깥으로 0.5 m 간격으로 진행하며 1 m 나갈 때마다 1칸 낮아진다. 높이 3 이하가 되면 멈춘다.
9. **나무**: 중심 18 m 밖, 지면 블록 위(물·고원·호숫가 제외), 다른 나무와 5×5 범위 안에서 겹치지 않게, 바이옴 개수만큼(최대 3000회 시도). `solid = 1`.
10. **바닥 장식**: 무작위 위치 2200회 시도, 물·나무 칸 제외. 구역별 장식 키 3개 중 하나(§10.1.5).

### 9.2 지형 메시 생성

- 칸마다 윗면 사각형 1개를 만든다.
- 동서남북 이웃이 더 낮으면(맵 밖은 0) 그 차이만큼 옆면 사각형을 1개 만든다.
- 정점 속성: `aFace`(0 윗면, 1 x축 옆면, 2 y축 옆면), `aType`(블록 종류), `aTop`(그 칸 윗면 높이, 옆면 테두리 계산용), `aUV`(윗면 = (x, y), x축 옆면 = (y, 높이), y축 옆면 = (x, 높이)).
- 블록 종류 번호: 0 잔디/흙, 1 잔디/돌, 2 모래, 3 사암, 4 눈/흙, 5 눈/돌, 6 돌.

- **지도 바탕**(v2.2, 지도 §10.4.1): 180×180 캔버스(`mapTerr`)에 칸 색(물 파랑, 나무 진녹색, 높을수록 밝게)을 칸당 1 px로 미리 그려 둔다. 별도로 같은 크기의 `mapSeen`에는 플레이어가 지나며 본 곳(반지름 30 m)만 0.2초마다 `mapTerr`에서 복사해 쌓는다(탐험 안개).

#### 10.1.1 픽셀 그리기 도구 `Spr` (MUST)

이미지 파일 없이 스프라이트를 코드로 찍는 작은 도구다. 논리 px 격자에 색 문자열을 채우고, 마지막에 외곽선을 두른 뒤 캔버스로 바꾼다.

```js
class Spr {                       // w×h 논리 px. 외곽선 자리로 사방 1 px 여백
  set(x, y, color)                // 점 하나
  rect(x, y, w, h, color)
  ell(cx, cy, rx, ry, color, shade=0)   // 타원. shade=1이면 왼쪽 위 밝게, 오른쪽 아래 어둡게 3단
  poly(points, color)             // 다각형 (픽셀 중심 내부 판정)
  line(x0, y0, x1, y1, color)     // 브레젠험
  moon(cx, cy, r, ox, oy, r2, color)    // 초승달 = 큰 원 − 어긋난 작은 원
  star(x, y, color, big)          // 십자 반짝이, 중심은 흰색
  outline(color)                  // 비어 있는 칸 중 4방향 이웃이 칠해진 칸을 외곽선 색으로
  canvas()                        // ImageData로 찍어 캔버스 반환
}
const mk = (w, h, draw) => { const s = new Spr(w, h); draw(s); s.outline('#140f2a'); return s.canvas(); };
const anim = draw => [draw(0), draw(1)];   // 2프레임
```

모든 스프라이트를 1024×1024 아틀라스 하나에 선반 방식으로 패킹하고(1 px 간격), `SPR[key] = [{u0, v0, u1, v1, w, h}, ...]`로 등록한다. 스프라이트 배치에서 월드 높이 hm을 주면 폭은 hm × w/h다.

#### 10.1.2 톤과 팔레트

- **주조색**: 밤 하늘 남보라(`#221c60` → `#9a82dc`), 꿈 잔디 청록(`rgb(.25,.59,.44)`), 솜사탕 분홍·라벤더(`#ffb3d9`, `#d9b3ff`), 금색 포인트(`#ffd23a`).
- **원소색**은 §6.1을 그대로 쓴다. 망토·투사체·이펙트·아이콘 테두리를 원소색으로 맞춰 "무슨 원소 빌드인지"가 화면에서 읽히게 한다.
- 구역 조명은 `uTint`로 곱한다. 구역 1은 너무 어둡지 않게(조명 틴트 (.84, .88, 1)), 구역 2는 따뜻하게, 구역 3은 차갑게.

#### 10.1.6 아이콘 (16×16 논리 px, MUST)

카드·HUD 슬롯·일시정지 목록에서 **글자를 읽지 않아도 무엇인지 알게** 한다.

- **기술 25종**: 원소색 ×0.32 어두운 타일 위에 아키타입 기호를 원소색으로 그리고, 오른쪽 아래에 원소 표식을 넣는다.
  - 아키타입 기호(12): 화살(bolt), 빛나는 공(orb), 심지 달린 폭탄(lob), 대각선 점 3개(barrage), 휘는 점선 + 화살촉(homing), 굵은 가로 광선(beam), 부채꼴(cone), 고리(nova), 점선 원(aura), 중심 + 위성 3개(orbit), 초승달 베기(strike), 지그재그(chain).
  - 원소 표식(8): 불꽃, 물방울, 잎, 번개, 눈 결정, 돌, 독방울, 별.

- 이벤트 분위기는 `G.evK`(0~1)만큼 3초에 걸쳐 섞고 끝나면 3초에 걸쳐 돌아온다.

#### 10.1.10 효과음·진동 (MUST, v2.2)

- 소리는 파일 없이 WebAudio로 즉석 합성한다(오실레이터 + 필터 잡음, 마스터 게인 0.5 → 컴프레서). 브라우저 규칙상 첫 키·터치 뒤에 컨텍스트를 만든다.
- 같은 소리는 최소 간격을 둔다(타격 0.045초, 처치 0.05초 등). 경험치 조각은 0.45초 안에 연달아 먹으면 음이 한 단계씩(최대 12) 올라간다.
- 소리 이름 25개: 타격·처치·경험치·코인·회복·점프·피격·레벨업·궁극기·보스 등장·경고(예고 시작)·폭발·번개·충격파·뿔피리(행진·최후의 무리)·이벤트·분노·징·승리·열기·클릭·포털·저주·원거리 발사·소환.
- 진동(`navigator.vibrate`, 터치 기기만): 피격(45ms, 큰 피해 [60,30,80]), 레벨업 [25,40,25], 궁극기 110, 보스 등장·처치, 충격파, 분노, 중간 보스 등장·처치, 이벤트, 포털, 근처 폭발 22ms.
- 우측 상단 미니맵 아래에 🔊 / 📳(터치 기기만) 토글. 설정은 localStorage(`dk.snd`, `dk.vib`)에 저장하되 막혀 있어도 동작한다. 시뮬레이션(`SIM`)에서는 소리·진동을 내지 않는다.

### 10.2 밸런싱 원칙

- **§6~§8의 수치를 그대로 쓴다.** 이 수치는 "구역 1을 처음 하는 사람이 7~9분에 보스를 깨우고 60% 정도 확률로 이기는" 감각을 목표로 한다.
- 수치는 data 섹션 표와 공식 함수(`xpNext`, `rollRarity` 등)에만 둔다. 로직 코드에 매직 넘버를 흩뿌리지 않는다.
- 밸런스 손잡이 3개를 spawning 섹션 맨 위 상수로 둔다.

```js
const SPAWN_K = 1.6;    // 생성 속도 마지막 계수
const XP_K    = 1.3;    // 꿈 조각 배율
const BOSS_HP = 2000;   // 보스 기본 HP(약한 빌드용 바닥값). 실제 HP는 화력 × 목표 시간(§8.4.1)
```

- §12.2 시뮬레이션 지표가 범위를 벗어나면 **아래 손잡이만** 조정하고 조정 내역을 보고한다. 다른 값은 건드리지 않는다.

| 증상 | 조정할 손잡이 | 조정 폭 |
|---|---|---|
| 첫 레벨업이 35초보다 늦음 / 300초 레벨 < 16 | XP_K | 1.3 → 최대 1.6 |
| 300초 레벨 > 26 | XP_K | 1.3 → 최소 1.0 |
| 120초 화면 적 < 60 | SPAWN_K | 1.6 → 최대 2.0 |
| 120초 화면 적 > 150, 또는 플레이테스트에서 구역 1 5분 전 사망 비율 > 50% | SPAWN_K | 1.6 → 최소 1.3 |
| 보스가 30초 안에 녹음 | `FIGHT` 목표 시간·`MINFIGHT` | 목표 시간 올림 / 최소 처치 시간 올림 |
| 보스전이 130초 넘게 걸림 | `DPS_SINGLE`, 목표 시간 | `DPS_SINGLE` 0.1 → 올림 / 목표 시간 내림(장기전은 탈진이 막음) |

> **보스 HP를 화력에 맞춘 이유**: 고정 HP(1100·1600·10000 시도)는 빌드(상성)에 따라 보스가 4초에 녹거나 100초 넘게 버텼다. 화력 × 목표 시간으로 맞추니 보통 난이도 44~50초에 모였다(§8.4.1).

- **원칙**: 플레이어가 강해지는 속도(레벨업 간격 15~60초)가 적이 강해지는 속도보다 *조금* 빨라야 한다. 구역이 바뀔 때 한 번 "벽"을 느끼게 한다(구역 배율 1 → 1.8 → 3.2).

#### 10.3.2 입력·안정성 (MUST)

- Enter·Space·방향키는 `preventDefault()`. 마우스로 누른 버튼에 포커스가 남아 Enter가 그 버튼을 한 번 더 누르는 것을 막는다. `startGame()`은 `G.state === 'menu'`일 때만 동작하고, 시작할 때 포커스를 푼다.
- 타이틀에서 `renderer.compile(scene, camera)`로 모든 셰이더를 미리 컴파일한다(첫 플레이 프레임 멈춤 방지).
- 게임 루프는 **다음 프레임을 먼저 예약**하고 update·render를 각각 try/catch로 감싼다. 에러가 나면 화면 아래에 빨간 줄로 "오류가 났어요. 이 문구를 알려 주세요 → (위치: 메시지 · 스택 첫 줄)"을 8초 띄우고 로그에 `error` 이벤트를 남긴다(3초에 한 번). 키 입력 처리도 같은 방식으로 감싼다.
- `dt = clamp(경과, 0, 0.05)` — 음수 dt를 막는다.

#### 10.4.1 지도 (v2.2)

- **미니맵**: 우상단 원형(96 px, 모바일 72 px, 내부 128×128). 기본은 **시점이 위로 오게 돌고**(`N` 키로 북쪽이 위로 고정), 플레이어 흰 화살표는 바라보는 방향. 보이는 반지름 22 / 34 / 52 m(`+`/`−`로 바꿈, 저장). 탐험한 곳만 지형이 보이고 나머지는 어둡다.
- **큰 지도**: `Tab`을 누르는 동안(또는 `M` 고정, 터치는 미니맵·🗺 버튼) 화면 가운데에 지도 + 범례. 게임은 멈추지 않는다. 북쪽 위 고정, `+`/`−`로 1~3배 확대(플레이어 중심).
- **표시 규칙**: 수호자 제단·포털은 탐험 여부와 상관없이 늘 표시하고, 미니맵 범위 밖이면 가장자리에 방향 표식으로 보인다. 그 밖의 오브젝트(상인·상자·비석·제단들·광석·열매)는 본 곳에서만 보인다. 수호자(보스)는 늘 보인다. 몬스터는 레이더 반경 42 m 안만.
- **모양**: 제단 = 마름모, 포털 = 고리, 상인·상자 = 네모, 룬 비석 = 삼각형, 광석·열매 = 점, 몬스터 = 작은 점(정예 노랑, 거대 큰 빨강, 우두머리·마술사 보라 네모, 보스 큰 빨강 마름모, 금빛 개체 노랑).
- 큰 지도 아래 범례 한 줄과 조작 안내를 보여 준다.

- **읽기**: 게임이 `https://raw.githubusercontent.com/Katonea/dream-knight/main/ranking.json`을 `fetch`(6초 제한, 캐시 무시 쿼리)해 상위 10개와 "지금 기록은 등록하면 N위예요"를 보여 준다. 불러오지 못하면(오프라인·아티팩트 같은 막힌 환경) 이 기기의 `localStorage` 기록(`dk.rank`, 최대 10)을 보여 주고 이유를 알린다. 내 기록은 금색 테두리.
- **쓰기**: 정적 사이트라 브라우저가 저장소에 직접 쓸 수 없다. 대신 **"랭킹에 등록"** 버튼이 기록(JSON)이 미리 채워진 GitHub 이슈 양식(`.github/ISSUE_TEMPLATE/ranking.yml`)을 새 창으로 연다(닉네임은 `localStorage dk.name`에 기억). 사용자가 **Submit new issue**를 누르면 `.github/workflows/ranking.yml`이 `.github/scripts/add-ranking.js`를 돌려 검사하고, 통과하면 `ranking.json`을 커밋·푸시한 뒤 "N위" 댓글을 달고 이슈를 닫는다. 반영까지 몇 분(raw 캐시 약 5분).
- **검사**: 점수를 게임과 같은 식 `(처치×2 + 시간×3 + 총피해/200 + (구역−1)×1500 + 수호자×800 + 6000) × (1 + 0.5×난이도)`로 다시 계산해 ±2 안인지, 시간 240~5400초, 수호자 3, 구역 3, 시작 기술 3종 중 하나, 닉네임 비어 있지 않음, 같은 닉네임·점수·시간 중복 아님, 한 계정 20건 이하. 닉네임에서 특수문자(`<>&"'` 등)를 지운다.
- **한계(MUST 알릴 것)**: 클라이언트에서 만든 기록이라 작정하면 조작할 수 있다. 공식 일치와 범위 검사만 한다. GitHub 로그인 없이는 등록할 수 없다.
- **입력창**: 닉네임 입력 중에는 게임 단축키(Enter·Space·방향키 등)가 먹지 않는다(`INPUT` 대상 keydown은 무시).
- **검증**: 결과 화면에 랭킹 표·내 순위·닉네임 입력·등록 버튼이 보인다 / 버튼이 `issues/new?template=ranking.yml&name=…&record=…` 주소로 연다 / 스크립트가 정상 기록은 올리고 점수 조작·너무 빠른 시간·중복은 거른다.

### 10.5 애매할 때의 기본값

- 수치가 표에 없다 → 비슷한 항목의 값을 쓰고 `// DECISION:` 주석.
- 연출이 정의되지 않았다 → 원소 색 + 흰색 파편 몇 개로 단순하게.
- 성능과 연출이 충돌한다 → 성능 우선(§12.1의 FPS 기준). 파편·숫자 상한을 먼저 줄인다.
- 이 문서와 다른 참고 자료가 충돌한다 → **이 문서가 우선**.

  while (q.length) { const i = q.pop(), x = i % N, y = (i / N) | 0;

      if (nx < 0 || ny < 0 || nx >= N || ny >= N || seen[j] || solid[j] || Math.abs(hmap[j] - hmap[i]) > 1) continue;
      seen[j] = 1; q.push(j); } }
  let stuck = 0; for (let i = 0; i < N * N; i++) if (hmap[i] < 2 && !seen[i]) stuck++; return stuck;
}

### 12.3 플레이테스트 KPI (핵심 재미 가설 검증, 테스터 5명 이상)

| 가설 | 측정 방법 | 성공 기준 |
|---|---|---|
| H1 성장 쾌감 | 9분 시점 분당 처치 ÷ 1분 시점 분당 처치(로그) | ≥ 5배. "강해지는 느낌" 5점 척도 평균 ≥ 4 |
| H2 빌드 선택 | 레벨업당 카드 고민 시간(`pick.ms`), 1번 카드 선택 비율 | 평균 ≥ 1.5초, 1번 선택 비율 ≤ 50% |
| H3 입체 지형 | 구역당 점프 횟수(`summary.jumps`), 고원 체류 시간 비율(`summary.highGroundSec`) | 점프 ≥ 30회/구역, 고원 체류 ≥ 10% |
| H4 목표 명확성 | 구역 1에서 보스를 깨운 시각(`bossWake`), 최후의 무리 전 보스 처치 비율 | 평균 5~9분, 처치 비율 ≥ 70% |
| 재도전 의향 | 결과 화면에서 "다시 하기"를 누른 비율 | ≥ 60% |
| 첫 판 이해도 | 설명 없이 1분 안에 이동·점프·레벨업 선택을 해냄 | 5명 중 4명 이상 |

이 지표를 위해 `G.log`에 `{t, event, value}`를 쌓는다. 이벤트: `start, zone, lvl, pick{i, ms}, banish, relic, bless, awaken, ult, bossWake, bossKill, flood, portal, win/lose, summary{jumps, highGroundSec, time, kills, lvl}`. 결과 화면의 "로그 복사" 버튼으로 JSON을 클립보드에 복사한다(SHOULD). 로그에는 개인정보를 넣지 않는다(시각·이벤트·수치만).

### 12.4 검증 실행 방법 (권장)

에디터 내장 미리보기 대신 **헤드리스 크롬 + CDP**로 검증한다(§11.2). Node 22 이상은 `WebSocket`이 내장이라 라이브러리가 필요 없다.

1. `chrome --headless=new --remote-debugging-port=<port> --window-size=1280,720 about:blank`
2. `http://127.0.0.1:<port>/json/list`에서 페이지의 `webSocketDebuggerUrl`을 얻어 연결
3. `Runtime.enable` → `Page.navigate(index.html)` → 2.5초 대기
4. 단계마다 `Runtime.evaluate({expression, awaitPromise: true, returnByValue: true})`로 `__game` API를 호출. 긴 시뮬은 영웅·구역 단위로 나눈다
5. `Runtime.exceptionThrown` 이벤트를 모아 에러 0개를 확인
6. `Page.captureScreenshot`으로 타이틀·구역 1~3·레벨업·모바일(390×844) 화면을 찍어 눈으로 확인
7. 측정 중 실시간 루프가 방해되면 `window.requestAnimationFrame = () => 0`으로 끄고 `update`/`render`를 직접 부른다
